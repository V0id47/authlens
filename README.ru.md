# AuthLens

**Автономный анализ аутентификации с проверяемыми свидетельствами.**

[English](README.md) · [Español](README.es.md) · [简体中文](README.zh-CN.md)

Python 3.11+ · MIT · v0.1.0 · без зависимостей во время выполнения. Локальный кандидат на выпуск; [проверки и оставшиеся условия](docs/release-readiness.md).

## Зачем нужен проект

Для проверки выгрузки журналов не обязательно загружать чувствительные данные в облако или разворачивать SIEM. AuthLens показывает связанные события, их происхождение и качество исходных данных. Индикатор — повод для проверки, а не доказательство компрометации.

## Возможности

Разбор SSH и строгого JSONL, нормализация UTC, включительные временные окна, повторяющиеся отказы, отказы для разных учётных записей и успех после отказов. Исключения, удаление повторов, SHA-256, номера строк, диагностика качества, структурированные журналы и отчёты text/JSON/CSV/Markdown/HTML на четырёх языках. Сетевых подключений и попыток входа нет.

## Демонстрация

Данные синтетические; IP-адреса предназначены для документации:

```console
authlens analyze examples/ssh-demo.log --input-format ssh --lang ru
authlens analyze examples/events.jsonl --format html --output demo-ru.html --lang ru
```

Ожидаются AL-001 (пять отказов для alice), AL-003 (последующий успех) и AL-002 (пять разных учётных записей). [Ожидаемый результат](examples/expected-findings.json).

## Архитектура

Ограниченное чтение и хеш → парсер → события UTC → исключения и повторы → окна с очередями и счётчиками → индикаторы со свидетельствами → локализованные отчёты. Ядро независимо от CLI и экспортёров. [Подробности](docs/architecture.md), [решения](docs/adr/0001-language.md).

Python 3.11–3.14. В каталоге проекта на Linux/macOS:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install .
```

Windows PowerShell:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install .

```

Без активации окружения используйте `.venv\Scripts\authlens.exe` вместо `authlens`. Установка может загружать средства сборки; выполнение автономно. Публикация на PyPI не заявлена. Локально проверены Windows/Python 3.12; публичная межплатформенная CI ещё требует запуска.

## Быстрый старт

```console
authlens analyze examples/events.jsonl --lang ru
authlens analyze examples/events.jsonl --format json --output report.json
```

Выберите новое имя файла в закрытом каталоге: отчёт содержит имена пользователей и IP.

## Использование

```console
authlens analyze --help
authlens analyze examples/events.jsonl --window-seconds 60 --burst-threshold 5
authlens analyze examples/events.jsonl --exclude-cidr 198.51.100.0/24 --exclude-user healthcheck
authlens analyze examples/events.jsonl --strict --fail-on MEDIUM --format json --log-file run.log
authlens analyze auth.log --input-format ssh --year 2026 --timezone=-03:00
```

Коды выхода: 0 — полный анализ; 1 — порог `--fail-on`; 2 — аргументы/конфигурация; 3 — I/O/лимит; 4 — неполные, некорректные данные или отсутствие событий для анализа; 130 — отмена. Неполнота важнее порога индикаторов. stdout содержит отчёт, stderr — диагностику. `--quiet` сохраняет отчёты и ошибки, `--verbose` добавляет счётчики. Текст уже без цвета.

## Формат результатов

JSON `schema_version=1.0` содержит версию, время UTC, хеш, счётчики, диагностику и действующие настройки. Индикатор разделяет наблюдение, интерпретацию, гипотезу, рекомендацию и безобидные объяснения. Есть важность, качественная уверенность, параметры, ссылки и до 20 событий-свидетельств. Ключи/ID/перечисления не переводятся. Для каждой пары правило/группа выводится первый эпизод, достигший порога. Пустой CSV содержит только заголовки; для качества данных без индикаторов нужен JSON. [Схема](docs/report-schema.json).

## Конфигурация

`--config examples/config.toml`; приоритет CLI > явно указанный TOML > значения по умолчанию. Неизвестные ключи и неверные типы/диапазоны отклоняются. По умолчанию: 300 секунд, пороги 5, файл 16 MiB, строка 16 KiB, 50 000 принятых записей до исключений/удаления повторов. [Справочник](docs/configuration.md).

## Языки

`--lang en`, `es`, `ru`, `zh-CN` или `language = "ru"` в TOML. Иначе определяется локаль ОС, резервный язык — английский. Каталоги устанавливаются в пакет; ключи и параметры форматирования проверяются тестами. Проверка носителями языка приветствуется; сертификация перевода не заявлена.

## Безопасность

В отчётах нет исходных строк и суффиксов SSH; в журналах выполнения нет идентичностей, путей и содержимого ввода. HTML/Markdown экранируются, формулы CSV нейтрализуются. Файлы никогда не перезаписываются. POSIX: режим 0600; Windows: ACL каталога. [Политика](SECURITY.md), [модель угроз](THREAT_MODEL.md).

## Область / разрешение

Анализируйте только собственные журналы или данные, на обработку которых есть разрешение. Область — локальный файл и исключения. Используйте неизменяемый экспорт и контролируемые каталоги. Хеш обозначает обработанные байты, но не подтверждает подлинность или цепочку хранения доказательств.

## Ограничения

Поддерживается документированная грамматика SSH и схема JSONL, не произвольный syslog, EVTX, VPN или веб-журналы. Традиционным датам нужны год и фиксированное смещение; движение времени назад отклоняется без угадывания года/DST. Нет GeoIP, репутации, атрибуции, ML и обнаружения медленных/распределённых атак. Точные повторы могут быть реальными событиями при грубой точности времени; `--keep-duplicates` сохраняет их. Ограничения не гарантируют фиксированное потребление RAM.

## Ложные срабатывания

Повторные попытки, устаревшие данные автоматизации, общий NAT, QA и сбои SSO дают схожие признаки. Успех после отказов может быть законным восстановлением. Без использованных паролей password spraying не подтверждается. MEDIUM/HIGH — приоритет проверки, не CVSS. [Логика правил](docs/detection-logic.md).
